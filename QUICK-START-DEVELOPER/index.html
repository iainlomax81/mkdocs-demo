🚀 Quick Start Overview

What You'll Be Working On

Agathas.Storefront is an e-commerce platform currently undergoing modernization from legacy ASP.NET MVC 2 (.NET Framework 3.5/4.0, circa 2010) to modern .NET 6+/ASP.NET Core with cloud-native capabilities.

Current State: - 7 Visual Studio projects in layered architecture (Presentation, Controllers, Services, Domain, Data Access, Infrastructure) - Domain-Driven Design with excellent aggregate boundaries (Product, Basket, Order, Customer) - 6,104 lines of code across 192 classes - Zero automated tests (this is changing - Phase 1 priority!) - Manual deployment to IIS on Windows

Modernization Phases: 1. Phase 1 (CURRENT): Establish testing foundation, eliminate critical vulnerabilities 2. Phase 2: Cloud migration with containerization, managed database, responsive design 3. Phase 3: Framework modernization (.NET 6+, ASP.NET Core, EF Core) 4. Phase 4: Optimization and feature enhancement

Your Role: Help modernize this well-architected application while preserving its excellent domain model

Key Documents for Developers: 1. System Architecture (45 min) - Understand layered architecture and patterns 2. Business Domain Model (30 min) - Understand business logic and aggregates 3. GLOSSARY.md (reference) - Terminology and technology definitions

Repository Setup

1. Clone Repository

# Clone the repository (replace with actual repository URL)
git clone https://github.com/[organization]/Agathas.Storefront.git
cd Agathas.Storefront

# Verify all files present
git status

2. Restore NuGet Packages

# Option 1: Visual Studio (recommended)
# Open Agathas.Storefront.sln in Visual Studio
# Right-click solution → Restore NuGet Packages

# Option 2: Command line
nuget restore Agathas.Storefront.sln

Expected Packages (from analysis): - ASP.NET MVC 2.0 - NHibernate 2.1 - StructureMap 2.5 - AutoMapper 1.1 - Log4Net 1.2 - jQuery 1.3.2 (in Scripts folder)

3. Database Setup

Create Local Databases:

-- Option 1: Use existing MDF files (if provided)
-- Files should be in Agathas.Storefront.UI.Web.MVC/App_Data/
-- Shop.mdf (main database)
-- aspnetdb.mdf (membership database)
-- User Instance mode will attach these automatically on first run

-- Option 2: Create databases manually (if MDF files not provided)
-- Open SQL Server Management Studio
-- Connect to localhost\SQLEXPRESS
CREATE DATABASE Shop;
GO

CREATE DATABASE aspnetdb;
GO

-- Then run schema creation scripts (if provided in /Database folder)

Connection String Configuration:

Check Agathas.Storefront.UI.Web.MVC/Web.config:

<connectionStrings>
  <!-- BEFORE: User Instance mode (may not work on modern SQL Server) -->
  <add name="Shop" connectionString="Data Source=.\SQLEXPRESS;AttachDbFilename=|DataDirectory|\Shop.mdf;User Instance=true;Integrated Security=SSPI" />

  <!-- AFTER: Standard connection (if User Instance fails) -->
  <add name="Shop" connectionString="Data Source=.\SQLEXPRESS;Initial Catalog=Shop;Integrated Security=SSPI" />
</connectionStrings>

Note: SQL Server User Instance is deprecated. If connection fails, switch to standard connection string and create databases manually.

4. Build Solution

# Option 1: Visual Studio
# Open Agathas.Storefront.sln
# Build → Build Solution (Ctrl+Shift+B)

# Option 2: MSBuild command line
msbuild Agathas.Storefront.sln /p:Configuration=Debug

Expected Build Output: All 7 projects build successfully - Agathas.Storefront.UI.Web.MVC - Agathas.Storefront.Controllers - Agathas.Storefront.Services - Agathas.Storefront.Model - Agathas.Storefront.Repository.NHibernate - Agathas.Storefront.Infrastructure

Build Warnings: Some warnings expected due to obsolete framework (ignore for now)

5. Run Application

Option 1: IIS Express (Recommended): 

1. Open Agathas.Storefront.sln in Visual Studio
2. Set Agathas.Storefront.UI.Web.MVC as startup project (right-click → Set as Startup Project)
3. Press F5 (Start Debugging) or Ctrl+F5 (Start Without Debugging)
4. Browser should open to http://localhost:[port]/

Option 2: Local IIS: 

1. Open IIS Manager
2. Create new application pool (.NET Framework 4.0, Integrated pipeline)
3. Add website pointing to Agathas.Storefront.UI.Web.MVC folder
4. Browse site in IIS Manager

Expected Result: Home page loads showing product catalog

Common First-Run Issues: See Troubleshooting section

🏗️ Understanding the Architecture

Domain-Driven Design Patterns

Aggregates (Business Entity Clusters):

  1. Product Aggregate (Root: ProductTitle)
  2. Purpose: Product catalog with variants (size/color)
  3. Entities: ProductTitle, Product, Brand, Category
  4. Value Objects: ProductSize, ProductColor

  5. Location: Agathas.Storefront.Model/Products/

  6. Basket Aggregate (Root: Basket)

  7. Purpose: Shopping cart management
  8. Entities: Basket, BasketItem
  9. Business Rules: No duplicate products (quantity increases), quantity > 0, delivery required

  10. Location: Agathas.Storefront.Model/Basket/

  11. Order Aggregate (Root: Order)

  12. Purpose: Placed order with state management
  13. Entities: Order, OrderItem
  14. Value Objects: Payment, ShippingService
  15. State Machine: Pending → Processing → Shipped → Delivered (or Cancelled)

  16. Location: Agathas.Storefront.Model/Orders/

  17. Customer Aggregate (Root: Customer)

  18. Purpose: Customer account with addresses
  19. Entities: Customer, DeliveryAddress
  20. Location: Agathas.Storefront.Model/Customers/

Reference: Business Domain Model

Request Flow (Current Architecture)

HTTP Request
    ↓
IIS / ASP.NET Runtime
    ↓
Global.asax (Routing)
    ↓
IoCControllerFactory (StructureMap DI)
    ↓
MVC Controller (e.g., ProductController)
    ↓
Service Layer (e.g., ProductService)
    ↓
Domain Model (e.g., ProductTitle aggregate)
    ↓
Repository Interface (e.g., IProductRepository)
    ↓
Repository Implementation (e.g., ProductRepository - NHibernate)
    ↓
Database (SQL Server)
    ↓
(Response flows back up the stack)
    ↓
View (ASPX) with ViewModel
    ↓
HTML Response to Browser

Key Points: - Controllers handle HTTP, map to view models - Services orchestrate business logic, coordinate aggregates - Domain enforces business rules, maintains invariants - Repositories abstract data access - No database logic in domain (pure business logic)

🛠️ Common Development Tasks

Task 1: Add a New Business Rule to Domain Model

Scenario: Add validation rule "Order total must be > $10"

Steps:

  1. Locate Domain Entity: Agathas.Storefront.Model/Orders/Order.cs

  2. Add Business Rule: 

    // In Order.cs
public class Order
{
    // Existing code...

    public decimal TotalAmount { get; private set; }

    // New method
    public void ValidateMinimumOrderAmount()
    {
        const decimal MinimumOrderAmount = 10.00m;
        if (TotalAmount < MinimumOrderAmount)
        {
            throw new DomainException(
                $"Order total must be at least ${MinimumOrderAmount}. Current total: ${TotalAmount}");
        }
    }

    // Call from constructor or setter
    public void SetTotalAmount(decimal amount)
    {
        TotalAmount = amount;
        ValidateMinimumOrderAmount(); // Enforce invariant
    }
}

  3. Update Unit Tests (FUTURE - tests don't exist yet, but will in Phase 1): 

    [Test]
public void Order_WithTotalLessThan10_ThrowsDomainException()
{
    // Arrange
    var order = new Order();

    // Act & Assert
    Assert.Throws<DomainException>(() => order.SetTotalAmount(5.00m));
}

  4. Build and Test: Ensure no existing functionality broken

Task 2: Add a New MVC Endpoint

Scenario: Add endpoint to get order history for a customer

Steps:

  1. Create Service Method in Agathas.Storefront.Services/Implementations/OrderService.cs: 

    public class OrderService : IOrderService
{
    private readonly IOrderRepository _orderRepository;

    public GetOrderHistoryResponse GetOrderHistory(GetOrderHistoryRequest request)
    {
        var customer = _customerRepository.GetById(request.CustomerId);
        if (customer == null)
            throw new ArgumentException("Customer not found");

        var orders = _orderRepository.GetOrdersByCustomer(customer.Id);

        return new GetOrderHistoryResponse
        {
            Orders = orders.Select(o => Mapper.Map<OrderViewModel>(o)).ToList()
        };
    }
}

  2. Add Controller Action in Agathas.Storefront.Controllers/Controllers/OrderController.cs: 

    public class OrderController : BaseController
{
    private readonly IOrderService _orderService;

    public OrderController(IOrderService orderService)
    {
        _orderService = orderService;
    }

    public ActionResult History(int customerId)
    {
        var request = new GetOrderHistoryRequest { CustomerId = customerId };
        var response = _orderService.GetOrderHistory(request);

        var viewModel = new OrderHistoryPageView
        {
            Orders = response.Orders
        };

        return View("OrderHistory", viewModel);
    }
}

  3. Create View Views/Order/OrderHistory.aspx: 

    <%@ Page Language="C#" MasterPageFile="~/Views/Shared/Site.Master" Inherits="System.Web.Mvc.ViewPage<OrderHistoryPageView>" %>

<asp:Content ID="Content1" ContentPlaceHolderID="TitleContent" runat="server">
    Order History
</asp:Content>

<asp:Content ID="Content2" ContentPlaceHolderID="MainContent" runat="server">
    <h2>Order History</h2>

    <% foreach (var order in Model.Orders) { %>
        <div class="order">
            <h3>Order #<%= order.Id %></h3>
            <p>Date: <%= order.OrderDate.ToShortDateString() %></p>
            <p>Total: $<%= order.TotalAmount %></p>
            <p>Status: <%= order.OrderState %></p>
        </div>
    <% } %>
</asp:Content>

  4. Add Routing (if custom route needed) in Global.asax.cs: 

    routes.MapRoute(
    "OrderHistory",
    "Order/History/{customerId}",
    new { controller = "Order", action = "History" }
);

  5. Test: Navigate to /Order/History/123 in browser

Task 3: Query Data with NHibernate

Scenario: Get all products in a specific category

Repository Method: 

// IProductRepository interface
public interface IProductRepository
{
    IList<Product> GetProductsByCategory(int categoryId);
}

// ProductRepository implementation
public class ProductRepository : IProductRepository
{
    private readonly ISession _session;

    public IList<Product> GetProductsByCategory(int categoryId)
    {
        return _session
            .CreateCriteria<Product>()
            .CreateAlias("ProductTitle", "pt")
            .CreateAlias("pt.Category", "cat")
            .Add(Restrictions.Eq("cat.Id", categoryId))
            .List<Product>();
    }
}

Note: Criteria API is NHibernate-specific. In Phase 3 (EF Core migration), this becomes: 

// EF Core equivalent
return _context.Products
    .Include(p => p.ProductTitle)
        .ThenInclude(pt => pt.Category)
    .Where(p => p.ProductTitle.Category.Id == categoryId)
    .ToList();

🐛 Troubleshooting

Issue 1: SQL Server User Instance Not Supported

Symptom: Error on startup: "User Instance feature is not supported on this version of SQL Server"

Cause: SQL Server User Instance mode deprecated in SQL Server 2012+

Solution:

  1. Create databases manually in SQL Server: 

    CREATE DATABASE Shop;
CREATE DATABASE aspnetdb;

  2. Update connection strings in Web.config: 

    <!-- BEFORE -->
<add name="Shop" connectionString="Data Source=.\SQLEXPRESS;AttachDbFilename=|DataDirectory|\Shop.mdf;User Instance=true;Integrated Security=SSPI" />

<!-- AFTER -->
<add name="Shop" connectionString="Data Source=.\SQLEXPRESS;Initial Catalog=Shop;Integrated Security=SSPI" />

  3. Run database schema scripts (if provided in /Database folder)

Issue 2: NuGet Package Restore Fails

Symptom: Error: "Unable to find version '2.1.0' of package 'NHibernate'"

Cause: Old NuGet package versions may not be available on default NuGet.org feed

Solution:

  1. Add fallback package source in Visual Studio:
  2. Tools → NuGet Package Manager → Package Manager Settings
  3. Package Sources → Add new source

  4. Name: "NuGet v2", Source: https://packages.nuget.org/api/v2/

  5. Manually download packages (last resort):

  6. Search https://www.nuget.org/packages for specific versions
  7. Download .nupkg files
  8. Place in local folder, add as package source

Issue 3: Build Warnings About Obsolete APIs

Symptom: Warnings like "System.Web.Mvc.Html.LinkExtensions.ActionLink is obsolete"

Cause: .NET Framework 3.5/4.0 APIs have obsolete warnings in modern Visual Studio

Solution: Ignore for now - these warnings are expected in legacy codebase. Will be resolved in Phase 3 (.NET 6+ migration).

Issue 4: jQuery 1.3.2 Script Errors in Browser Console

Symptom: JavaScript errors in browser console related to jQuery

Cause: jQuery 1.3.2 is very old and may conflict with modern browser features

Solution: - For now: Test in Chrome or Firefox (better backward compatibility) - Phase 1 fix: Update to jQuery 3.6+ (security vulnerability fix)

Issue 5: Missing Log Files Directory

Symptom: Application crashes with "Access denied" or "Directory not found" for C:\logs\

Cause: Log4Net configured to write to C:\logs\ but directory doesn't exist or insufficient permissions

Solution:

  1. Create logs directory: 

    mkdir C:\logs

  2. Grant permissions (if needed): 

    icacls C:\logs /grant "IIS AppPool\DefaultAppPool:(OI)(CI)F"

  3. OR change log path in Web.config to App_Data: 

    <log4net>
  <appender name="FileAppender" type="log4net.Appender.FileAppender">
    <file value="App_Data\application.log" /> <!-- Changed from C:\logs\ -->
  </appender>
</log4net>
