General Terms

12-Factor App

A methodology for building modern, cloud-native applications with twelve principles: codebase, dependencies, config, backing services, build/release/run, processes, port binding, concurrency, disposability, dev/prod parity, logs, and admin processes.

Agathas.Storefront Status: Achieves 4/12 factors (codebase, dependencies, build/release, logs partially)
Reference: Cloud Readiness Assessment

C4 Model

A hierarchical approach to architecture diagramming with 4 levels: Context (system in environment), Container (high-level tech choices), Component (internal structure), Code (class diagrams/implementation).

Usage: All architecture diagrams in this documentation use C4 model conventions
Reference: System Architecture

Monolithic Architecture

An architectural pattern where all components of an application are built as a single, indivisible unit. Contrast with microservices where components are independently deployable.

Agathas.Storefront Implementation: Single deployable web application with all layers bundled
Reference: System Architecture

Technical Debt

The implied cost of rework caused by choosing quick/easy solutions instead of better approaches. Includes outdated technologies, missing tests, poor documentation, and code quality issues.

Agathas.Storefront Status: High technical debt due to technology obsolescence, zero test coverage, scalability limitations
Reference: System Architecture - Technical Debt

Architecture & Design Patterns

Aggregate Root

A Domain-Driven Design pattern where one entity serves as the entry point to an aggregate (cluster of related entities). All external access goes through the aggregate root, which enforces invariants.

Agathas.Storefront Implementation: 4 aggregate roots: ProductTitle, Basket, Order, Customer
Code Location: Agathas.Storefront.Model namespace
Reference: Business Domain Model

Dependency Injection (DI)

A design pattern where dependencies are provided to a class from external sources rather than created internally, enabling loose coupling and testability.

Agathas.Storefront Implementation: StructureMap 2.5 IoC container configured in BootStrapper.cs
Code Location: Agathas.Storefront.UI.Web.MVC/BootStrapper.cs
Reference: System Architecture

Domain-Driven Design (DDD)

An approach to software development that emphasizes collaboration between technical and domain experts, using a rich domain model that reflects business concepts.

Agathas.Storefront Maturity: High - implements entities, value objects, aggregates, domain events, ubiquitous language, and encapsulated business rules
Reference: Business Domain Model

Factory Pattern

A creational design pattern that provides an interface for creating objects without specifying exact classes, delegating instantiation logic to factory methods.

Agathas.Storefront Implementation: IoCControllerFactory creates MVC controllers via StructureMap
Code Location: Agathas.Storefront.Controllers/IoCControllerFactory.cs
Reference: System Architecture - ADR-004

Layered Architecture (N-Tier)

An architectural pattern organizing code into horizontal layers, each with specific responsibilities. Dependencies flow downward; higher layers depend on lower layers but not vice versa.

Agathas.Storefront Layers: 5 layers - Presentation (MVC), Services, Domain, Data Access, Infrastructure
Reference: System Architecture - Level 2 Container Diagram

Repository Pattern

A design pattern that abstracts data access behind an interface, providing collection-like access to domain objects without exposing database implementation details.

Agathas.Storefront Implementation: Repository interfaces in Agathas.Storefront.Model, implementations in Agathas.Storefront.Repository.NHibernate
Code Examples: IProductRepository, IBasketRepository, IOrderRepository, ICustomerRepository
Reference: Data Architecture

State Pattern

A behavioral design pattern that allows an object to change its behavior based on internal state, encapsulating state-specific behavior in separate state classes.

Agathas.Storefront Implementation: Order lifecycle management with OrderState enum (Pending, Processing, Shipped, Delivered, Cancelled)
Code Location: Agathas.Storefront.Model/Orders/OrderState.cs
Reference: Business Domain Model - Order Aggregate

Unit of Work Pattern

A pattern that maintains a list of objects affected by a business transaction and coordinates writing changes to the database, ensuring all changes succeed or fail as a single unit.

Agathas.Storefront Implementation: NHUnitOfWork class wrapping NHibernate ISession with transaction management
Code Location: Agathas.Storefront.Repository.NHibernate/NHUnitOfWork.cs
Reference: Data Architecture

Value Object

A Domain-Driven Design concept for objects that have no conceptual identity, defined only by their attributes. Two value objects with identical attributes are considered equal.

Agathas.Storefront Examples: Address, Payment, ProductSize, ProductColor
Code Location: Agathas.Storefront.Model namespace
Reference: Business Domain Model

Technologies & Frameworks

.NET Framework

Microsoft's software framework for building Windows applications. Includes Common Language Runtime (CLR), Base Class Library (BCL), and APIs for various application types.

Agathas.Storefront Version: 3.5 (2008) and 4.0 (2010)
Status: ⚠️ Out of mainstream support, obsolete
Modernization Target: .NET 6+ or .NET 8 LTS
Reference: Technology Inventory

ASP.NET MVC

Microsoft's web application framework implementing the Model-View-Controller pattern for building web applications with separation of concerns.

Agathas.Storefront Version: ASP.NET MVC 2 (released March 2010)
Status: ⚠️ Obsolete, 15+ years old
Key Features Used: Controllers, Views (ASPX), Model Binding, Routing, Action Filters
Modernization Target: ASP.NET Core MVC 6+ or Razor Pages
Reference: System Architecture

AutoMapper

An object-to-object mapping library that eliminates tedious mapping code between DTOs and domain entities using convention-based configuration.

Agathas.Storefront Version: AutoMapper 1.1 (circa 2010)
Usage: Mapping domain entities to view models, service requests/responses to domain objects
Code Location: AutoMapperBootStrapper.cs in Controllers and Services projects
Reference: System Architecture - Component Diagram

jQuery

A fast, small JavaScript library simplifying HTML DOM manipulation, event handling, animation, and Ajax for rapid web development.

Agathas.Storefront Version: jQuery 1.3.2 (released February 2009)
Status: ⚠️ CRITICAL - Known security vulnerabilities (CVE-2011-4969, CVE-2012-6708, CVE-2015-9251)
Usage: Form validation, AJAX basket updates, UI interactions
Modernization Target: Modern JavaScript framework (React, Vue, or vanilla JS ES6+)
Reference: Vulnerability Assessment

Log4Net

A flexible logging framework for .NET applications, part of the Apache Logging Services project, supporting multiple output targets and log levels.

Agathas.Storefront Version: Log4Net 1.2
Configuration: File-based logging to C:\logs\
Status: ⚠️ Not cloud-compatible (local file system dependency)
Code Location: Agathas.Storefront.Infrastructure/Logging/
Modernization Target: Structured logging with cloud-native sink (Application Insights, ELK, CloudWatch)
Reference: Observability Setup

StructureMap

An Inversion of Control (IoC) container for .NET providing dependency injection capabilities with convention-based registration and lifecycle management.

Agathas.Storefront Version: StructureMap 2.5
Status: ⚠️ Outdated (current version 4.x, but recommend built-in DI)
Configuration: BootStrapper.cs with registry scanning
Usage: Controller factory, service resolution throughout application
Modernization Target: Built-in ASP.NET Core Dependency Injection
Reference: System Architecture - ADR-004

Database & ORM

NHibernate

An open-source Object-Relational Mapping (ORM) framework for .NET, porting Hibernate from Java, providing automatic persistence for .NET objects to relational databases.

Agathas.Storefront Version: NHibernate 2.1 (circa 2009)
Status: ⚠️ Outdated (current version 5.x)
Mapping Strategy: XML-based mappings (HBM.XML files)
Features Used: Lazy loading, first-level cache, transactions, criteria queries
Code Location: Agathas.Storefront.Repository.NHibernate project
Modernization Target: Entity Framework Core 6+ with code-first migrations
Reference: Data Architecture

SQL Server Express LocalDB

A lightweight version of SQL Server Express targeted at developers, supporting automatic database file attachment without service installation.

Agathas.Storefront Version: SQL Server Express with User Instance mode
Database Files: - App_Data\Shop.mdf - Main application database (15 tables, 9 entities) - App_Data\aspnetdb.mdf - ASP.NET Membership database Status: ⚠️ User Instance mode deprecated, not production-ready
Limitations: Single-server only, cannot scale horizontally, no high availability
Modernization Target: Managed database service (Azure SQL, RDS, Cloud SQL)
Reference: Data Architecture

Lazy Loading

An ORM pattern where related entities are not loaded from database until explicitly accessed, reducing initial query overhead but risking N+1 query problems.

Agathas.Storefront Implementation: Enabled by default in NHibernate configuration
Risk: N+1 query problems evident in product listing and order history (from analysis)
Evidence: No eager loading configured in repository layer
Reference: Query Performance Analysis

HBM.XML Mapping

NHibernate's XML-based mapping format defining how .NET classes map to database tables and columns, alternative to attributes or fluent configuration.

Agathas.Storefront Usage: All entity mappings defined in XML files
Location: Agathas.Storefront.Repository.NHibernate/Mapping/*.hbm.xml
Entities Mapped: Product, ProductTitle, Basket, BasketItem, Order, OrderItem, Customer, DeliveryAddress
Modernization Target: Entity Framework Core code-first with Fluent API
Reference: Data Architecture - ORM Mappings

Security & Compliance

ASP.NET Membership

Microsoft's legacy authentication and authorization system providing user account management, password storage, and role management for ASP.NET applications.

Agathas.Storefront Version: ASP.NET Membership 2.0
Database: aspnetdb.mdf with standard membership schema
Status: ⚠️ Deprecated - Microsoft recommends ASP.NET Core Identity
Features Used: Forms authentication, user registration, login
Security Issues: Outdated password hashing (SHA1), no MFA support
Modernization Target: ASP.NET Core Identity or external identity provider
Reference: Security Controls

CVE (Common Vulnerabilities and Exposures)

A standardized identifier for publicly known cybersecurity vulnerabilities, maintained by MITRE Corporation.

Agathas.Storefront Critical CVEs: - jQuery 1.3.2: CVE-2011-4969, CVE-2012-6708, CVE-2015-9251 (XSS vulnerabilities) - .NET Framework 3.5/4.0: Multiple security patches no longer available
Reference: Vulnerability Assessment

GDPR (General Data Protection Regulation)

European Union regulation on data protection and privacy requiring organizations to protect EU citizens' personal data and privacy rights.

Agathas.Storefront Status: ❌ Non-compliant
Missing Requirements: Data subject rights (erasure, portability, access), consent management, cookie consent, privacy by design, DPIA, breach notification
Risk: Fines up to 4% of annual revenue or €20M (whichever is greater)
Reference: Compliance and Regulatory

PCI DSS (Payment Card Industry Data Security Standard)

Security standard for organizations handling credit cards, requiring secure handling, storage, and transmission of cardholder data.

Agathas.Storefront Status: ✅ Compliant via delegation to PayPal
Strategy: No cardholder data stored or processed locally; all payment processing delegated to PayPal Payment Gateway
Scope: SAQ A (Simplest compliance level - no direct card handling)
Reference: Compliance and Regulatory

Plaintext Secrets

Security anti-pattern where sensitive credentials (passwords, API keys, connection strings) are stored unencrypted in configuration files or source code.

Agathas.Storefront Issue: Web.config contains plaintext connection strings, SMTP credentials, PayPal API credentials
Risk: High - credentials exposed in source control, accessible to anyone with file system access
Evidence: Web.config lines 15-35 (connection strings), lines 87-95 (mailSettings)
Remediation: Environment variables, Key Vault, Secret Manager, encrypted configuration sections
Reference: Vulnerability Assessment

WCAG (Web Content Accessibility Guidelines)

International standards for making web content accessible to people with disabilities, published by W3C Web Accessibility Initiative.

Agathas.Storefront Status: ❌ Unknown/Not tested
Target Level: WCAG 2.1 Level AA
Likely Issues: No ARIA labels, keyboard navigation unknown, color contrast unknown, screen reader compatibility untested
Reference: Compliance and Regulatory

Business Domain - E-Commerce

Aggregate (DDD)

A cluster of domain objects (entities and value objects) treated as a single unit for data changes, with a root entity controlling access and enforcing invariants.

Agathas.Storefront Aggregates: 1. Product Aggregate (Root: ProductTitle) - Product catalog with variants (sizes/colors) 2. Basket Aggregate (Root: Basket) - Shopping cart with items and delivery options 3. Order Aggregate (Root: Order) - Placed order with items, payment, shipping 4. Customer Aggregate (Root: Customer) - Customer account with delivery addresses

Reference: Business Domain Model

Basket (Shopping Cart)

E-commerce domain concept representing a customer's temporary collection of products intended for purchase, including quantities and delivery selections.

Agathas.Storefront Implementation: Basket aggregate root with BasketItem entities
Business Rules: No duplicate products (increases quantity instead), quantity > 0, delivery option required for checkout
Code Location: Agathas.Storefront.Model/Basket/Basket.cs
Reference: Business Domain Model - Basket Aggregate

Domain Event

A pattern for communicating significant occurrences within the domain to other parts of the system, enabling loose coupling between aggregates.

Agathas.Storefront Implementation: OrderSubmittedEvent published when order is placed
Infrastructure: Static DomainEvents class with in-process handler registration
Current Usage: Low - only 1 event implemented (opportunity to expand)
Code Location: Agathas.Storefront.Model/Orders/OrderSubmittedEvent.cs
Reference: Business Domain Model - Domain Events

Order Lifecycle

The sequence of states an order transitions through from creation to completion or cancellation.

Agathas.Storefront States: Pending → Processing → Shipped → Delivered (or Cancelled)
Implementation: State Pattern with OrderState enum
State Transitions: Validated and controlled by business rules in Order class
Code Location: Agathas.Storefront.Model/Orders/Order.cs
Reference: Business Domain Model - Order State Machine

Product Variant

E-commerce concept where a master product (e.g., "Designer Dress") has multiple purchasable variants differing by attributes like size and color.

Agathas.Storefront Model: ProductTitle (master) → multiple Product (variants) with ProductSize and ProductColor
Pricing: Defined at ProductTitle level, inherited by all variants
Code Location: Agathas.Storefront.Model/Products/
Reference: Business Domain Model - Product Aggregate

Development & Operations

CI/CD (Continuous Integration / Continuous Deployment)

DevOps practices automating code integration, testing, and deployment to reduce manual effort and increase release frequency.

Agathas.Storefront Status: ❌ Not implemented
Current Process: Manual build in Visual Studio, manual deployment to IIS
Impact: Slow deployment, high risk of human error, no automated testing
Modernization Target: GitHub Actions, Azure DevOps, or similar CI/CD platform
Reference: Deployment Process

IIS (Internet Information Services)

Microsoft's web server for hosting ASP.NET applications on Windows, providing HTTP request handling, application pooling, and SSL/TLS termination.

Agathas.Storefront Hosting: IIS 7.0+ or IIS Express for local development
Configuration: Integrated Pipeline mode, .NET Framework 4.0 app pool
Status: ⚠️ Tied to Windows hosting, not cloud-native
Modernization Target: Cross-platform hosting (Kestrel, containerized deployment)
Reference: Infrastructure Topology

MSBuild

Microsoft's build platform for compiling .NET applications, processing project files (.csproj) and orchestrating build tasks.

Agathas.Storefront Usage: Visual Studio 2010+ project format, solution-level builds
Build Time: Not measured (no CI/CD pipeline)
Modernization Target: SDK-style project format (.NET 6+), faster builds
Reference: Build Process

User Instance (SQL Server)

A SQL Server Express feature allowing automatic database file attachment per user, deprecated in SQL Server 2012 in favor of LocalDB.

Agathas.Storefront Usage: Connection string includes AttachDbFilename with User Instance=true
Status: ⚠️ Deprecated, not supported in modern SQL Server
Issues: Not production-ready, cannot scale, requires full SQL Server on client
Evidence: Web.config connection string (line 18)
Modernization Target: Managed database service with proper connection pooling
Reference: Data Architecture - Database Technology
