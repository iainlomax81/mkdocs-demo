2.2 Requirements Specification

Document Version: 1.0
Date: 2026-06-09
Status: Current State Analysis (Reverse-Engineered)
Standard: Based on IEEE 29148-2018 (Requirements Engineering)

Executive Summary

This document captures the functional and non-functional requirements of the Agathas Storefront e-commerce platform as implemented in the current system. Requirements have been reverse-engineered from source code, user interfaces, configuration files, and system behavior analysis.

Key Findings: - Total Requirements Identified: 85+ functional and non-functional requirements - Requirements Coverage: Core e-commerce functionality well-implemented; advanced features (inventory, returns, internationalization) not present - Requirements Maturity: Basic e-commerce requirements fully met; scalability and compliance requirements partially met - Business Priority: Customer-facing transaction workflows (browse, basket, checkout) prioritized over administrative features

Requirements Distribution:

Category Requirements Implementation Status
Functional Requirements 55 80% Complete
Non-Functional Requirements 20 65% Complete
User Interface Requirements 10 75% Complete
Data Requirements 5 90% Complete
Integration Requirements 5 100% Complete
Compliance Requirements 8 40% Complete

1. Functional Requirements

1.1 Product Catalog Management

FR-PC-001: Product Browsing

Priority: 🔴 CRITICAL
Status: ✅ Implemented
Description: Users shall be able to browse products organized by categories and brands.

Acceptance Criteria: - Products displayed in hierarchical category structure - Featured products shown on home page - Product listings show image, name, price - Category navigation via menu and breadcrumbs

Implementation: - Controller: ProductController.Index() - Service: ProductCatalogService.GetProductsByCategory() - View: Views/Product/Index.aspx

Traceability: Maps to User Journey "Product Discovery" in Business Domain Model

FR-PC-002: Product Filtering and Refinement

Priority: 🟡 HIGH
Status: ✅ Implemented
Description: Users shall be able to filter product listings by size, color, brand, and price range.

Acceptance Criteria: - Filter options displayed in sidebar - Filter combinations applied using AND logic - Filtered results update product listing - Filter state persists during browsing session

Implementation: - Service: ProductSearchRequestQueryGenerator generates NHibernate queries from filter criteria - JSON: JsonProductSearchRequest captures filter selections - Query: Dynamic NHibernate criteria queries

Traceability: Supports business capability "Product Discovery"

FR-PC-003: Product Detail View

Priority: 🔴 CRITICAL
Status: ✅ Implemented
Description: Users shall be able to view detailed information for a specific product including all available variants.

Acceptance Criteria: - Product image, name, description, price displayed - All size and color combinations shown - Add to basket functionality available - Product title and variant attributes visible

Implementation: - Controller: ProductController.Detail(int productId) - View: Views/Product/Detail.aspx - ViewModel: ProductView with size/color options

Traceability: Essential for product selection in shopping workflow

FR-PC-004: Featured Products Display

Priority: 🟡 HIGH
Status: ✅ Implemented
Description: System shall display featured products on the home page to promote specific items.

Acceptance Criteria: - Configurable featured products list - Featured products shown on landing page - Products link to detail pages

Implementation: - Controller: HomeController.Index() - Service: ProductCatalogService.GetFeaturedProducts()

Business Value: Marketing and promotion support

1.2 Shopping Basket Management

FR-BK-001: Add Product to Basket

Priority: 🔴 CRITICAL
Status: ✅ Implemented
Description: Users shall be able to add products to their shopping basket with specified quantity.

Acceptance Criteria: - Select size and color variant - Specify quantity (default: 1) - Product added to basket with confirmation - If product already in basket, quantity increased

Implementation: - Controller: BasketController.Add() - Service: BasketService.AddProductToBasket() - Domain: Basket.Add() enforces no-duplicate rule - Storage: Cookie-based basket persistence

Business Rule: BR-BSK-001 (No duplicate products - increases quantity instead)

Traceability: Core requirement from Shopping Workflow

FR-BK-002: View Basket Contents

Priority: 🔴 CRITICAL
Status: ✅ Implemented
Description: Users shall be able to view all items in their basket with quantities and prices.

Acceptance Criteria: - List all basket items with product details - Show quantity per item - Display item subtotal (price × quantity) - Show basket subtotal (all items) - Show delivery cost - Show basket total (items + delivery)

Implementation: - Controller: BasketController.Index() - View: Views/Basket/Index.aspx - ViewModel: BasketView with calculated totals

Traceability: Required before checkout

FR-BK-003: Update Item Quantity

Priority: 🔴 CRITICAL
Status: ✅ Implemented
Description: Users shall be able to increase or decrease quantities of items in the basket.

Acceptance Criteria: - Quantity can be increased or decreased - Minimum quantity is 1 (removing item if decreased to 0) - Basket totals recalculate automatically - Changes persist across page loads

Implementation: - Controller: BasketController.UpdateQuantity() - Service: BasketService.UpdateBasketItemQuantity() - Domain: BasketItem.IncreaseItemQtyBy(), BasketItem.DecreaseItemQtyBy()

Business Rule: BR-BSK-002 (Positive quantity)

FR-BK-004: Remove Item from Basket

Priority: 🟡 HIGH
Status: ✅ Implemented
Description: Users shall be able to remove items from their basket.

Acceptance Criteria: - Remove button available per item - Item removed immediately - Basket totals recalculate - Empty basket message shown if no items remain

Implementation: - Controller: BasketController.Remove(int basketItemId) - Service: BasketService.RemoveItemFromBasket() - Domain: Basket.Remove(basketItem)

FR-BK-005: Select Delivery Option

Priority: 🔴 CRITICAL
Status: ✅ Implemented
Description: Users shall be able to select a delivery option with associated cost before checkout.

Acceptance Criteria: - Delivery options displayed with names and costs - User selects one delivery option - Delivery cost included in basket total - Delivery option selection persists

Implementation: - Controller: BasketController.SetDeliveryOption(int deliveryOptionId) - Domain: Basket.SetDeliveryOption() - Entity: DeliveryOption with pricing

Business Rule: BR-BSK-004 (Delivery option required before checkout)

FR-BK-006: Basket Persistence

Priority: 🟡 HIGH
Status: ✅ Implemented
Description: Basket contents shall persist across user sessions using cookie storage.

Acceptance Criteria: - Basket saved in cookie after each modification - Basket restored on subsequent visits - Cookie expires after configurable period - Anonymous and authenticated users both supported

Implementation: - Repository: CookieBasketRepository - Storage: ICookieStorageService - Key: CookieDataKeys.Basket

Traceability: Supports user experience for interrupted shopping sessions

1.3 User Account Management

FR-AC-001: Customer Registration

Priority: 🔴 CRITICAL
Status: ✅ Implemented
Description: New users shall be able to create a customer account with email and password.

Acceptance Criteria: - Registration form with email, password, first name, surname - Email uniqueness validation - Password strength validation - Account created in both domain (Customer) and infrastructure (Membership) - Auto-login after successful registration

Implementation: - Controller: AccountRegisterController.Register() - Service: CustomerService.CreateCustomer() - Domain: Customer entity - Infrastructure: ASP.NET Membership Provider

Business Rule: BR-CUS-001 (Unique email), BR-CUS-002 (Email validation)

FR-AC-002: User Login

Priority: 🔴 CRITICAL
Status: ✅ Implemented
Description: Registered users shall be able to authenticate using email and password.

Acceptance Criteria: - Login form with email and password fields - Credentials validated against membership database - Authentication cookie created on success - Redirect to originally requested page after login - Error message on failure

Implementation: - Controller: AccountLogOnController.LogOn() - Service: AspMembershipAuthentication.Login() - Infrastructure: ASP.NET Forms Authentication

FR-AC-003: Social Authentication

Priority: 🟡 HIGH
Status: ✅ Implemented
Description: Users shall be able to authenticate using social login providers (Facebook, Google, etc.) via Janrain.

Acceptance Criteria: - Social login buttons displayed on login page - Redirect to Janrain authentication - Token received from Janrain on success - User account created or linked - Auto-login after social auth

Implementation: - Controller: AccountLogOnController.JanrainCallback() - Service: JanrainAuthenticationService - Configuration: Janrain API key in Web.config

Business Rule: BR-AUT-003 (Social auth option)

FR-AC-004: User Logout

Priority: 🟡 HIGH
Status: ✅ Implemented
Description: Authenticated users shall be able to log out of their session.

Acceptance Criteria: - Logout link available when authenticated - Authentication cookie cleared - Redirect to home page - Session state cleared

Implementation: - Controller: AccountLogOnController.LogOut() - Infrastructure: FormsAuthentication.SignOut()

FR-AC-005: Manage Delivery Addresses

Priority: 🔴 CRITICAL
Status: ✅ Implemented
Description: Customers shall be able to add, edit, and delete delivery addresses.

Acceptance Criteria: - View list of saved delivery addresses - Add new address with street, city, postcode, name - Edit existing address - Delete address (if not only address) - Select address during checkout

Implementation: - Controller: CustomerController.AddDeliveryAddress() - Service: CustomerService.AddDeliveryAddress() - Domain: Customer.AddDeliveryAddress(), DeliveryAddress entity

Business Rule: BR-CUS-003 (Checkout address requirement), BR-ADR-001 (Required fields)

1.4 Checkout and Order Processing

FR-CO-001: Initiate Checkout

Priority: 🔴 CRITICAL
Status: ✅ Implemented
Description: Users shall be able to proceed from basket to checkout process.

Acceptance Criteria: - Checkout button available in basket view - Authentication required (redirect to login if not authenticated) - Basket must have items and delivery option selected - Checkout page displays basket summary and delivery address selection

Implementation: - Controller: CheckoutController.Index() - Authorization: [Authorize] attribute enforces authentication - Validation: Delivery option and items validated

Business Rule: BR-AUT-001 (Checkout authentication)

FR-CO-002: Select Delivery Address

Priority: 🔴 CRITICAL
Status: ✅ Implemented
Description: During checkout, customers shall select a delivery address from their saved addresses.

Acceptance Criteria: - List of customer's saved addresses displayed - Customer selects one address for delivery - Address details shown (street, city, postcode) - Option to add new address if none exist

Implementation: - Controller: CheckoutController.SelectAddress() - View: Address selector in checkout page - Validation: At least one address required

FR-CO-003: Submit Order

Priority: 🔴 CRITICAL
Status: ✅ Implemented
Description: Customers shall be able to confirm and submit their order for payment.

Acceptance Criteria: - Order created from basket contents - Order includes items, quantities, prices (snapshot) - Delivery address captured - Shipping service assigned - Order saved to database - Redirect to payment gateway

Implementation: - Controller: CheckoutController.Submit() - Service: OrderService.CreateOrderFromBasket() - Domain: Order entity created from Basket - Mapping: BasketItem → OrderItem with price snapshot

Business Rule: BR-CRS-001 (Order from basket), BR-ORD-006 (Price snapshot)

FR-CO-004: Process Payment via PayPal

Priority: 🔴 CRITICAL
Status: ✅ Implemented
Description: Customers shall complete payment securely through PayPal payment gateway.

Acceptance Criteria: - Redirect to PayPal with order details - PayPal presents payment UI - Customer completes payment - PayPal callback received with transaction status - Order updated with payment details on success

Implementation: - Controller: PaymentController.Callback() - Service: PayPalPaymentService generates payment request - Domain: Order.SetPayment() captures payment - Integration: HTTPS POST to PayPal sandbox endpoint

Business Rule: BR-PAY-001 (External processing), BR-PAY-004 (Amount validation), BR-ORD-002 (Payment amount match)

Security: BR-PAY-002 (No card storage)

FR-CO-005: Order Confirmation

Priority: 🔴 CRITICAL
Status: ✅ Implemented
Description: After successful payment, customers shall receive order confirmation via email and on-screen.

Acceptance Criteria: - Confirmation page displayed with order number - Order details shown (items, total, delivery address) - Confirmation email sent to customer email - Order status set to Submitted

Implementation: - Controller: CheckoutController.Confirmation() - Event: OrderSubmittedEvent raised when order submitted - Handler: OrderSubmittedHandler sends email - Service: IEmailService.SendOrderConfirmation()

Traceability: Completes Checkout Workflow

Acceptance Criteria: - Orders displayed in reverse chronological order (newest first) - Each order shows order number, date, total, status - Click order to view details

FR-OM-002: View Order Details

Acceptance Criteria: - Order date and order number displayed - Items ordered with product details, quantity, price - Subtotal, shipping cost, total amount - Delivery address - Payment details (amount, date, transaction ID) - Order status

Implementation: - Controller: OrderController.Detail(int orderId) - Service: OrderService.GetOrderDetail() - ViewModel: OrderView with items, payment, shipping

2. Non-Functional Requirements

2.1 Performance Requirements

NFR-PERF-001: Page Load Time

Priority: 🟡 HIGH
Status: ⚠️ Partially Met
Requirement: Product listing and detail pages shall load within 2 seconds under normal load.

Current Performance: - No performance monitoring implemented - Server-side rendering with ASPX views (slower than modern SPAs) - No CDN for static assets - Database queries not optimized (N+1 query issues possible with NHibernate)

Evidence: No Application Performance Monitoring (APM) detected in observability-setup.json

Recommendation: Implement APM (Application Insights), optimize queries, add caching

NFR-PERF-002: Concurrent Users

Priority: 🟡 HIGH
Status: ❌ Not Met
Requirement: System shall support at least 100 concurrent users without degradation.

Current Limitations: - Single-server architecture (LocalDB, in-process session) - Cannot scale horizontally - No load testing performed

Evidence: From cloud-readiness.json: "Cannot scale horizontally, single-server architecture"

Recommendation: Externalize state, migrate to cloud-scalable architecture

NFR-PERF-003: Database Query Performance

Priority: 🟡 HIGH
Status: ⚠️ Partially Met
Requirement: Database queries shall execute within 500ms for 95th percentile.

Current Implementation: - NHibernate ORM with lazy loading - Batch size configured (10) - SQL logging enabled (show_sql=true) - No query performance monitoring

Evidence: From data-architecture.json: "Good domain-to-database mapping"

Gaps: No query performance metrics, potential N+1 query issues

2.2 Scalability Requirements

NFR-SCAL-001: Horizontal Scaling

Priority: 🔴 CRITICAL
Status: ❌ Not Met
Requirement: System architecture shall support horizontal scaling to handle increased load.

Current Blockers: - In-process session state (per-server) - LocalDB (cannot be shared across servers) - File-based logging (local file system) - No load balancer support

Evidence: From cloud-readiness.json: "Fail - Cannot scale horizontally"

Recommendation: Externalize session (Redis), migrate database (Azure SQL), implement stateless architecture

NFR-SCAL-002: Database Scalability

Priority: 🟡 HIGH
Status: ❌ Not Met
Requirement: Database shall support scaling to 1 million+ products and 10,000+ orders per day.

Current Limitations: - SQL Server Express LocalDB (10GB limit) - No read replicas or sharding - Single database instance

Recommendation: Migrate to cloud database with auto-scaling (Azure SQL)

2.3 Availability and Reliability

NFR-AVAIL-001: System Uptime

Priority: 🔴 CRITICAL
Status: ⚠️ Unknown
Requirement: System shall maintain 99.9% uptime (43.8 minutes downtime per month).

Current State: - No health check endpoints - No automated failover - Single-server deployment (single point of failure) - No monitoring or alerting

Evidence: From observability-setup.json: "No APM, no metrics"

Recommendation: Implement health checks, multi-region deployment, monitoring

NFR-AVAIL-002: Error Handling

Priority: 🟡 HIGH
Status: ⚠️ Partially Met
Requirement: System shall gracefully handle errors without exposing sensitive information.

Current Implementation: - Custom error pages configured (Web.config) - Try-catch blocks in controllers - Logging via Log4Net

Gaps: - Error details may leak in development mode - No centralized error tracking - No user-friendly error recovery guidance

2.4 Security Requirements

NFR-SEC-001: Authentication

Priority: 🔴 CRITICAL
Status: ✅ Met
Requirement: System shall authenticate users before accessing protected resources (checkout, order history).

Implementation: - ASP.NET Forms Authentication - [Authorize] attributes on protected controllers - Authentication cookie with timeout - Social authentication option (Janrain)

Evidence: Authentication configuration in Web.config

NFR-SEC-002: Password Storage

Priority: 🔴 CRITICAL
Status: ✅ Met
Requirement: Passwords shall be stored securely using hashing (not plaintext).

Implementation: - ASP.NET Membership Provider - Passwords hashed by membership provider - Salt added automatically

Evidence: Membership provider configured in Web.config

NFR-SEC-003: Payment Security

Priority: 🔴 CRITICAL
Status: ✅ Met
Requirement: System shall NOT store credit card data; payment processing delegated to PCI-compliant provider.

Implementation: - All payment processing via PayPal - No card data captured or stored in application - Redirect to PayPal for payment UI - Only transaction ID stored

Business Rule: BR-PAY-001, BR-PAY-002

Compliance: PCI DSS compliance by delegation

NFR-SEC-004: HTTPS

Priority: 🔴 CRITICAL
Status: ⚠️ Configuration-Dependent
Requirement: All payment and authentication pages shall be served over HTTPS.

Current State: - HTTPS required for production (IIS configuration) - Development mode may use HTTP - No HTTPS redirect enforced in code

Recommendation: Enforce HTTPS redirect in application code, implement HSTS header

NFR-SEC-005: SQL Injection Prevention

Priority: 🔴 CRITICAL
Status: ✅ Met
Requirement: System shall prevent SQL injection attacks through parameterized queries.

Implementation: - NHibernate ORM (parameterized queries) - No raw SQL concatenation detected - HBM.XML mappings define safe queries

Evidence: All database access via NHibernate repository pattern

NFR-SEC-006: Cross-Site Scripting (XSS) Prevention

Priority: 🔴 CRITICAL
Status: ⚠️ Partially Met
Requirement: System shall prevent XSS attacks through input validation and output encoding.

Current Implementation: - ASP.NET request validation (ValidateRequest=true) - HTML encoding in views - No Content Security Policy (CSP) headers

Gaps: - No CSP headers - jQuery 1.3.2 has known XSS vulnerabilities

Recommendation: Update jQuery, implement CSP headers, review all user input handling

2.5 Usability Requirements

NFR-USAB-001: Browser Compatibility

Priority: 🟡 HIGH
Status: ⚠️ Partially Met
Requirement: System shall be compatible with modern browsers (Chrome, Firefox, Safari, Edge).

Current Support: - Designed for IE 7+ and Firefox 3+ (2010 era) - jQuery 1.3.2 (very old, limited modern browser testing) - ASPX views with server-side rendering

Risk: Modern browser compatibility untested

Recommendation: Test on current browser versions, update client libraries

NFR-USAB-002: Mobile Responsiveness

Priority: 🟡 HIGH
Status: ❌ Not Met
Requirement: System shall provide responsive design for mobile and tablet devices.

Current State: - Fixed-width design (not responsive) - No mobile-specific views - No viewport meta tag - Desktop-only layout

Evidence: From ui-inventory.json: No responsive design detected

Recommendation: Implement responsive CSS framework (Bootstrap), mobile-first design

2.6 Maintainability and Supportability

NFR-MAINT-001: Code Modularity

Priority: 🟡 HIGH
Status: ✅ Met
Requirement: System shall maintain clear separation of concerns with layered architecture.

Implementation: - 5-layer architecture (Presentation, Service, Domain, Data, Infrastructure) - Dependency injection (StructureMap) - Repository and Unit of Work patterns - Interface-based design

Evidence: Application Layers shows excellent separation

NFR-MAINT-002: Logging

Priority: 🟡 HIGH
Status: ⚠️ Partially Met
Requirement: System shall log errors, warnings, and key business events for troubleshooting.

Implementation: - Log4Net framework - File-based logging (C:\logs) - Configurable log levels - Error logging in controllers

Gaps: - No centralized log aggregation - File-based logs not suitable for cloud - No structured logging - No business event logging

Recommendation: Implement Application Insights, structured logging, business event tracking

NFR-MAINT-003: Configuration Management

Priority: 🟡 HIGH
Status: ❌ Not Met
Requirement: System configuration shall be externalized and environment-specific.

Current State: - Configuration in Web.config (hardcoded) - Secrets in Web.config (PayPal credentials, SMTP credentials) - No environment variables - No Azure App Configuration or Key Vault

Evidence: From configuration-inventory.json: "Hardcoded configuration"

Recommendation: Externalize configuration, use Azure Key Vault for secrets

Could Have (Future): - ❌ Product recommendations - ❌ Wish list - ❌ Promo codes - ❌ Guest checkout - ❌ Order tracking - ❌ Returns/refunds - ❌ Product reviews

Won't Have (This Phase): - ❌ Multi-language support - ❌ Multi-currency support - ❌ Marketplace model - ❌ Subscription model

9. Summary and Recommendations

9.1 Requirements Coverage Assessment

Strengths: - ✅ Core e-commerce transaction flow complete (browse → basket → checkout → payment → confirmation) - ✅ Clean domain model with business rules enforcement - ✅ Payment security through PCI-compliant provider - ✅ User authentication with social login option

Critical Gaps: - ❌ No automated testing (0% coverage) - ❌ GDPR non-compliance (data subject rights) - ❌ No inventory management (overselling risk) - ❌ Cannot scale horizontally (architectural limitation) - ❌ No mobile responsiveness - ❌ No admin portal (product/order management)

9.2 Modernization Requirements Priorities

Phase 1 - Critical (Immediate): 1. Implement automated testing (unit, integration, E2E) 2. Add GDPR compliance features (consent, data deletion, data export) 3. Implement inventory management with stock tracking 4. Externalize configuration and secrets 5. Add health check endpoints and monitoring

Phase 2 - High (3-6 months): 1. Mobile-responsive redesign 2. Implement admin portal 3. Add product search 4. Scale-out architecture (externalize state, cloud database) 5. Performance optimization and caching

Phase 3 - Medium (6-12 months): 1. Product recommendations engine 2. Order tracking and fulfillment 3. Returns/refunds processing 4. Promo code system 5. Multi-payment methods
